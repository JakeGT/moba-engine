# Vendor SDK features (DLSS, NRD, RTXDI, SHaRC, Streamline, FSR 4, XeSS)

The renderer can compile in NVIDIA, AMD and Intel SDKs behind cargo features
([ADR-0020](../adr/0020-next-gen-foundations.md) §6 and amendment 6). They are **off by
default**: `cargo build` needs no proprietary SDK, and public releases ship that open build only
([RELEASE.md](../../RELEASE.md) step 8). In N0 a back end is only probed at start-up; nothing
reaches the frame until its phase (N1 upscalers, N7/N8 lighting, N9 frame generation).

## Features

The features live on `moba-render` and are forwarded with the same names by `moba-client` and
`moba-engine` (under `render`). No server crate can reach them (the layering check).

| Feature | Slot | SDK | Builds on | Run-time binary |
|---|---|---|---|---|
| `fsr3` (default) | upscaler | none in N0 (FSR 3.1 shaders arrive in N1) | all | — |
| `dlss` | upscaler (1st) | DLSS 310.9.16 | Linux, Windows | NGX loads `libnvidia-ngx-dlss.so.310.9.16` / `nvngx_dlss.dll` |
| `fsr4` | upscaler (2nd) | FidelityFX SDK 2.4.0 | Linux, Windows (headers) | `amd_fidelityfx_{loader,upscaler}_vk.dll`, Windows only |
| `xess` | upscaler (3rd) | XeSS 3.0.2 | Linux, Windows (headers) | `libxess.dll`, Windows only |
| `nrd` | denoiser | NRD 4.18.0 (built from source with CMake) | Linux, Windows | none (static library) |
| `rtxdi` | direct lighting | RTXDI 3.1.0 | all | none (shader library) |
| `sharc` | radiance cache | SHaRC 1.8.3 | all | none (shader headers) |
| `streamline` | frame generation | Streamline 2.14.16 | Linux, Windows (headers) | `sl.interposer.dll`, Windows only |

Aggregates: `nvidia = dlss, nrd, rtxdi, sharc`; `vendor-sdks = nvidia, fsr4, xess`;
`dlss-fg = dlss, streamline`. `fsr4` is development-only (ADR-0020 Q6).

## Fetching

```bash
scripts/fetch-sdks.sh --only dlss,rtxdi      # or --only vendor-sdks,dlss-fg, or no option for all
scripts/fetch-sdks.sh --present-features     # prints the features whose SDKs are fetched
```

On Windows: `scripts\fetch-sdks.ps1 -Only dlss,rtxdi` (or Git Bash with the `.sh`).

- `vendor-sdks.toml` pins every archive: an official GitHub release asset or tag/commit
  archive, its SHA-256 (cross-checked against GitHub's release `digest` where one is
  published), and the SHA-256 of its licence file. Submodules and CMake downloads (RTXDI's
  library, NRD's ShaderMake and MathLib) are entries of their own, unpacked where the SDK's
  build expects them.
- SDKs land in `${MOBA_SDK_DIR:-target/vendor-sdks}/<name>-<tag>/`; archives are cached in
  `downloads/` and re-verified on reuse. A `.moba-sdk-sha256` stamp marks a verified unpack.
- **A changed licence fails the fetch.** The new text is kept as `changed-licence-*` beside
  the SDK; read it, and the PR that updates `licence_sha256` records the re-read.
- The script only downloads and unpacks. Nothing inside an archive is ever run by it.

## Building

```bash
cargo build -p moba-client --features dlss,rtxdi,sharc
```

- `build.rs` reads `MOBA_SDK_DIR` (default `target/vendor-sdks`) and **never downloads**. A
  missing or stale SDK fails the build with the fetch command to run.
- FFI declarations are generated by `bindgen` into `OUT_DIR` from the fetched headers; nothing
  derived from an SDK is committed. `bindgen` needs **libclang** (set `LIBCLANG_PATH` if it is
  not found; the runner images and Arch's `clang` package have it).
- `nrd` also needs **CMake 3.30+** (`CMAKE` overrides the path) and the **Vulkan SDK's `dxc`**
  (on `PATH`, or `%VULKAN_SDK%\Bin\dxc.exe` on Windows). The configure step is fully
  disconnected: `FETCHCONTENT_FULLY_DISCONNECTED=ON`, ShaderMake and MathLib from the fetched
  entries, `NRD_NRI=OFF`, `SHADERMAKE_FIND_DXC=OFF`, `SHADERMAKE_FIND_FXC=OFF`,
  `SHADERMAKE_FIND_DXC_VK=ON`, SPIR-V embeds only, static library.
- Linking: NGX's static library (`libnvsdk_ngx.a` plus `stdc++`/`dl` on Linux,
  `nvsdk_ngx_d.lib` on Windows); NRD statically; FSR 4, XeSS and Streamline are opened at run
  time with `libloading`, so a feature build still starts without them.

## Packaging the run-time binaries

Copy the binaries a feature loads **next to the executable**; the engine never searches the
system library path for them (a planted library elsewhere is ignored). NGX itself looks for the
DLSS feature binary beside the executable and in the driver. Do not ship any of them in a public
release.

## Selection and fallback

At renderer start-up each slot takes the first compiled-in back end the device supports, in the
order of the table above; later candidates for a filled slot are not probed. Every candidate
that is compiled in but unavailable logs **exactly one line**, then a summary follows:

```text
[vendor] dlss unavailable: NGX found no DLSS 310.9.16 feature binary (libnvidia-ngx-dlss.so.310.9.16) beside the executable or in the driver (NVSDK_NGX_Result_FAIL_FeatureNotFound); upscaler falls back to builtin
[vendor] selected: upscaler=builtin denoiser=builtin direct_lighting=rtxdi radiance_cache=sharc frame_generation=off latency=reflex compiled=dlss,… rtxdi=[…] sharc=[…]
```

The fallbacks are `builtin` (upscaler, denoiser, direct lighting), `none` (radiance cache) and
`off` (frame generation). The open build logs no `[vendor]` line. Reflex
(`VK_NV_low_latency2`) and Anti-Lag (`VK_AMD_anti_lag`) need no feature; `latency=` reports
which the device offers. `Renderer::vendor_backends()` returns the same choice as data. The
selection is a trait object chosen inside `crates/render/src/vendor/`; no call site outside it
uses `cfg`.

The RTX 5070 Ti run with every Linux-buildable back end is in
[perf/0029](../perf/0029-vendor-sdks.md).

## Verification and CI

- `scripts/agent-verify.sh --full` checks `moba-engine --features sim,net,render,fsr3`
  (`--all-features` would need the SDKs), then clippy, the selection tests and an engine check
  with every feature whose SDK is fetched. `nrd` is skipped without CMake and `dxc`.
- The `vendor-sdks` CI job (Linux and Windows) installs libclang, CMake and the Vulkan SDK,
  restores the archive cache keyed on `vendor-sdks.toml`, fetches and verifies
  `vendor-sdks,dlss-fg`, then builds and links `moba-client --features vendor-sdks`, runs
  clippy and the selection tests, and re-checks that no server crate reaches the vendor crates.
- `deny.toml` checks the `all-features` graph, which includes `bindgen`, `clang-sys`,
  `libloading`, `cmake` and their dependencies.

## Bumping an SDK

1. Change the entry's `tag`, `url`, `commit` and `version`; run the fetch. It fails on the
   archive hash: check the new archive came from the official repository, then update
   `sha256` (and `github_digest` where GitHub publishes one).
2. If the licence check fails, read the new licence in full, compare it with ADR-0020 §6a and
   `THIRD_PARTY.md`, and record the re-read in the PR before updating `licence_sha256`.
3. Re-run the build with the feature, the selection tests and, on a GPU, the fallback check.

## Notices and credits

`THIRD_PARTY.md` lists each feature's licence and obligations. The DLSS licence also asks for
NVIDIA marks in the in-game credits, splash screen and about box, and NVIDIA must be notified
before any commercial release (RELEASE.md step 8).

**Follow-up:** the client has no credits or about screen yet. When one is added, it must show
the notices and marks for every vendor feature compiled in (from `VendorBackends::compiled`).
