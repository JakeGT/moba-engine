# Performance log — M6 HUD and fog

## UI renderer
- One graphics pipeline, one host-visible vertex buffer per frame in flight (65,536 vertices ×
  36 B ≈ 2.25 MiB each; only the used prefix is uploaded), one combined-image-sampler
  descriptor set and the checked-in 128×64 RGBA glyph/icon atlas.
- UI is drawn after the 3D scene inside the existing dynamic-rendering pass with depth test
  off and alpha blending. The atlas is uploaded once with sync2 barriers and sampled with
  nearest filtering; solid rectangles use the white texel.
- Text is one textured quad per glyph (was one quad per lit font pixel). A typical HUD is a
  few hundred vertices; the Tab scoreboard remains far inside the 65k budget.
- Ability, inventory and shop rows add 8×8 icon cells from the same atlas (no new pipeline).
- `HudModel` is built once per frame from either the network snapshot or the local sim and
  supplies tick/phase/countdown/score/wave/unit-count to both HUD modes.
- The UI draw list retains capacity across frames; HUD text is formatted into fixed
  256-byte stack buffers (`HudString`/`hud_fmt!`), so steady-state HUD frames have no heap
  allocation (draw-list growth is warmed on the first frame).

## Fog of war
- Up to 16 allied vision circles (heroes/structures first, then minions) are uploaded in the
  existing camera UBO (384 B now, still one buffer).
- Terrain fragment shader evaluates 16 signed-distance tests with smooth edges; no texture,
  no extra geometry and no protocol cost. Server-side visibility filtering remains the
  authority and already withholds unseen units.
- Verified under lavapipe with `MOBA_VULKAN_VALIDATION=required`; captures:
  `docs/images/m6-hud-fog.png`, `docs/images/m6-scoreboard.png`.

## Spectator
Spectators receive every unit (no fog queries) with the same delta encoding; gold/inventory
are zeroed. Rendering reuses the normal scene/UI path with the free camera, so the only extra
cost is the larger visible set.

## Minimap and health bars
- Minimap and floating health bars reuse the same UI batch; lane geometry is drawn as thin
  rotated quads and unit dots are 3–5 px squares. No extra pipeline or pass.
- Health bars project world positions through the camera once per visible hero/structure; the
  work is O(visible units), ~10–20 per frame in lane fights.

## Progression HUD and shop
- The HUD adds one XP bar, a gold label, six inventory boxes and an eight-row shop panel;
  the whole screen remains inside the 65k-vertex UI budget (shop + HUD ≈ 30k).
- Progression updates are field-masked per hero. Gold changes for the owning player only;
  inventory changes only on purchase; level/XP change on kills. Wire growth is negligible.

## Network delta after protocol v8
Scores (8 B), outcome (1 B), hero pick (1 B per new entity), progression (field-masked) and
phase/countdown (3 B) add ~0.1–0.3 KiB/s at 30 snapshots/s. A fresh 30 s, 10-client soak on
plaintext protocol v6 (10 clients, 5% loss, 20 s) measured 4.6–6.8 KiB/s downstream and
1.16–1.23 KiB/s upstream. Encrypted protocol v6 measured 5.0–7.3 KiB/s downstream and
1.8–1.9 KiB/s upstream (12 s v8 encrypted: 5.4–9.2 KiB/s down / 1.74–1.92 KiB/s up).
Protocol v7 (spectator handshake) plaintext measured 4.7–7.6 KiB/s
down and 1.15–1.22 KiB/s up over 15 s. Protocol v8 (ready/surrender masks add 4 B/snapshot)
measured 4.8–7.7 KiB/s down and 1.14–1.23 KiB/s up over 15 s; protocol v9 (content catalogue
adds a one-time ~0.8 KiB handshake) measured 5.2–8.8 KiB/s down and 1.13–1.23 KiB/s up
over 12 s; protocol v10 (item/hero/ability/map catalogues, fragmented handshake) measured
5.2–9.2 KiB/s down and 1.14–1.23 KiB/s up over 12 s — still inside the 20/40 KB/s and
4 KB/s budgets (the AEAD tag adds 16 B per datagram, and encrypted input retries account for
the upstream rise).

## Next
- Floating health bars and minimap should reuse the UI batch (world→screen projection).
- If UI grows past 65k vertices, switch to instanced glyph quads before raising the budget.

## HUD model boundary

`hud/model.rs` is the only client HUD module that names `moba_net` types. Other modules draw
through `HudUnit` and `map_lanes`/`map_walls` wrappers, so network/protocol changes do not
spread through healthbar, minimap and geometry code. The golden fingerprint remained exact
after the boundary refactor.

## Textured atlas (0.2.x)

`UiVertex` now carries UV/atlas data. Text is one textured quad per glyph instead of one quad
per lit font pixel, reducing vertices by roughly 15–20×. The atlas is baked offline by
`cargo run -p moba-tools --bin bake-ui-atlas -- crates/render/assets/ui-atlas.rgba` and sampled
with nearest filtering; solid rectangles use the atlas white texel. Lavapipe capture is
unchanged (zero mean/max fingerprint difference) and validation reports no messages.
