# Performance log — M6 HUD and fog

## UI renderer
- One extra graphics pipeline and one host-visible vertex buffer per frame in flight
  (65,536 vertices × 24 B = 1.5 MiB each); only the used prefix is uploaded.
- No texture, sampler, descriptor set or extra render pass. UI is drawn after the 3D scene
  inside the existing dynamic-rendering pass with depth test off and alpha blending.
- Text is emitted as one quad per lit font pixel. A typical HUD is ~2–5k vertices; the Tab
  scoreboard is ~15–25k, well inside the 65k budget.
- The UI draw list retains capacity across frames; no per-frame allocation after warm-up
  beyond formatted strings.

## Fog of war
- Up to 16 allied vision circles (heroes/structures first, then minions) are uploaded in the
  existing camera UBO (384 B now, still one buffer).
- Terrain fragment shader evaluates 16 signed-distance tests with smooth edges; no texture,
  no extra geometry and no protocol cost. Server-side visibility filtering remains the
  authority and already withholds unseen units.
- Verified under lavapipe with `MOBA_VULKAN_VALIDATION=required`; captures:
  `docs/images/m6-hud-fog.png`, `docs/images/m6-scoreboard.png`.

## Network delta after protocol v2
Scores (8 B), outcome (1 B) and spawn hero pick (1 B per new entity) add ~0.1–0.2 KiB/s
at 30 snapshots/s. A fresh 30 s, 10-client soak on protocol v2 measured 4.0–5.2 KiB/s
downstream (including initial full snapshots) and ~1.2 KiB/s upstream — still far inside
the 20/40 KB/s and 4 KB/s budgets.

## Next
